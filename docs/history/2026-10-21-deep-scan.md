# Deep scan (`scan_chat`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A seventh read-only tool, `scan_chat`, that reads the recent history of one chat into memory page by page, matches it with fragment / words / regex / fuzzy rules, and returns the hits with an honest coverage header. Nothing on disk.

**Architecture:** Pure matching in `tgmcp/match.py`; the scan loop in `server.py` over the unchanged `Gateway.history`; `ScanResult` in `models.py`; bench category `scan`.

**Tech Stack:** stdlib only (`re`, `unicodedata`, `time`, `asyncio`).

**Spec:** `docs/history/2026-10-21-deep-scan-design.md` (§3 tool, §4 loop, §5 matching, §6a rulings).

## Global Constraints

- Read-only: `scan_chat` calls only `gateway.history`; the contract test stays green with no allowlist change; names avoid the denylist.
- Bounds: `max_messages` 100–20 000 (default 3 000), `limit` 1–100 (default 30), `tolerance` 0–2, regex pattern ≤ 200 chars, `SCAN_TIMEOUT_S = 60`, `PAGE_SIZE = 100`, `PAGE_PAUSE_S = 0.25`, text cap 2 000 chars on returned hits, result budget 30 000 bytes.
- Hidden chats invisible; `topic`/`since`/`until` go to `history`; `sender` filtered in memory (id or `@username` via `Directory`).
- `encoding="utf-8"`, LF, English, Garden Club examples only (no owner-related words); gate `check.py` exits 0; commits end with the writing model's Co-Authored-By.

## Review Focus

1. A regex like `(a+)+$` or `(.*)*` must be refused before any page is fetched, and a 200+ char pattern too. (Task 1, Task 2)
2. A scan on a chat shorter than `max_messages` must report `reached_start=True`, `stopped_by="start"`; with `since` inside the chat, `stopped_by="since"`. (Task 2)
3. `Busy` on the first page → `ToolError`; after a page → partial result with `stopped_by="flood"`, hits so far, the sentence in `note`. (Task 2)
4. Hits are the newest `limit`; `scanned` and `oldest_scanned` describe the pages actually read; the early stop never reports more coverage than read. (Task 2)
5. Tolerance clamps: a 3-letter query word never fuzzy-matches; "tracto" with tolerance 1 matches "tractor"; "trackor" does not match "tractor" with tolerance 1 but does with 2 — and "track" (5 letters, tolerance clamped to 1) does not match "tractor". (Task 1)

### Task 1: `tgmcp/match.py`

**Files:** Create `tgmcp/match.py`; Test `tests/test_match.py`

**Interfaces (Produces):**
```python
MAX_PATTERN_CHARS = 200
class PatternRefused(ValueError): ...   # message: "That pattern could run forever; simplify it." or "The pattern is longer than 200 characters."
def fold(text: str) -> str                       # lower, NFD, strip combining marks, ł→l, Ł→l, ё→е
def words_of(text: str) -> list[str]             # re.findall(r"\w+", folded text)
def trigrams(word: str) -> frozenset[str]        # of f"  {word} " padded; empty for len < 2
def levenshtein(a: str, b: str, max_distance: int) -> int   # early exit: returns max_distance + 1 when exceeded
def clamp_tolerance(word: str, tolerance: int) -> int       # ≤3 → 0; 4–6 → min(1, t); else t
def fuzzy_word(query_word: str, text_word: str, tolerance: int) -> bool   # clamp; trigram Jaccard ≥ 0.3 gate (skip gate when tolerance 0 → exact); then levenshtein ≤ tolerance
def fragment(query: str, text: str) -> bool      # folded substring (tolerance 0)
def words(query: str, text: str, tolerance: int = 0) -> bool   # every query word matches some text word (exact when 0, fuzzy_word otherwise)
def fragment_fuzzy(query: str, text: str, tolerance: int) -> bool   # ruling 3: each query word fuzzy-matches a text word OR is an exact substring of one
def compile_pattern(pattern: str) -> re.Pattern[str]   # IGNORECASE; refuses >200 chars, nested quantifiers (\((?:[^()]*[+*])\)[+*]) and back-references (\\\d|\(\?P=); documented heuristic
def regex(compiled: re.Pattern[str], text: str) -> bool    # compiled.search(text[:4096]) on the ORIGINAL text
def matcher(mode: str, query: str, tolerance: int) -> Callable[[str], bool]   # builds the predicate once per scan (compiles the regex, folds the query)
```

### Task 2: `scan_chat`

**Files:** Modify `tgmcp/models.py` (`ScanResult`, `StoppedBy = Literal["max_messages","since","start","time","flood","limit"]`), `tgmcp/server.py` (the tool, `SCAN_TIMEOUT_S`, `PAGE_SIZE`, `PAGE_PAUSE_S`, `_scan` helper, `guarded` accepts a per-tool timeout), `docs/tools.md`; Test `tests/test_tools_scan.py`

**Interfaces (Produces):** the tool exactly as spec §3; `ScanResult` fields as spec §3; `note` sentences per `stopped_by`:
- start: "Scanned all {scanned} messages of {title}; the whole chat was covered."
- max_messages: "Scanned the last {scanned} messages of {title} back to {oldest:%Y-%m-%d}; the chat continues further back."
- since: "Scanned {scanned} messages of {title} from {since:%Y-%m-%d} on."
- time: "Scanned {scanned} messages of {title} back to {oldest:%Y-%m-%d} before the 60-second budget ran out; call again with since/until to continue."
- flood: "Scanned {scanned} messages of {title} back to {oldest:%Y-%m-%d}; Telegram asked to wait {n} seconds, so the scan stopped there."
- limit: "Found the newest {limit} hits within the last {scanned} messages of {title} (back to {oldest:%Y-%m-%d}); older hits may exist."
Loop per spec §4 with rulings 1, 2, 5, 7: `before_id` cursor = last message id of the page; a page shorter than `PAGE_SIZE` ends the scan (`since` vs `start` by ruling 5); `asyncio.sleep(PAGE_PAUSE_S)` between pages; the clock is `time.monotonic` injected for tests (`clock` attribute on the module); `sender` resolved before the first page. Texts of hits through `cap_text`; `fit_budget` → `truncated`. `guarded` gets a `timeout_s` parameter (default `TOOL_TIMEOUT_S`); `scan_chat` uses `SCAN_TIMEOUT_S`.
